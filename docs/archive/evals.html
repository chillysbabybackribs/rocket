What changes

The panel

  • Two tabs: Scenarios and Tool health (today's Configure → Tools, kept as is).
  • Removed: the Braintrust sidebar, Overview, Logs, Playgrounds, Experiments, Datasets, Scorers, Compare/Diff/Tie, the disabled + buttons, and the mock sample data.
  • The Playwright cases (rocket-ui-regression) leave this panel; they stay in check:ui and the Braintrust CLI.

A scenario's page

  • The message can be edited and run straight away. That is the playground. "Save to scenario file" writes it back to the JSONL.
  • The grid is providers × trials. Cells fill in live, and each one shows a bar per grader.
  • "Earlier runs" is the history. Every run is saved by the host, with per-grader results, the message it used, and time and usage, so it survives a reload. The Passed and time columns show the change from the run you compare with.
  • Run all and Run again spend usage. Each starts only on a click and says so beside the button.

One run

  • Opens inside the eval panel: graders with reasons, files changed, tool calls, time and usage, and the transcript. "Open as chat" moves it into the chat column only if you want it there.
  • Eval chats stay out of the normal chat list.

Behind it

  • Each run works in a fresh temporary copy of the test project, outside this repo, so it can't touch real work or get credited with it.
  • New graders: files_unchanged, reply matches a pattern, time and usage limits, and a judge: a different provider reads the turn against a sentence you write.
  • Runs go through the same hub path as today (startEvalCell / finishEvalCell), and the app map keeps the actions models can drive.

Prior turns

  • Optional, per scenario: turns that come before the message, each with the provider that answered it. With none, a run starts a new chat as today.
  • Recorded (default) writes the turns and their file changes into the run's chat and folder. No provider holds a session for them, so every provider gets them through the real handoff path. Deterministic, and no setup turns.
  • Live sends them to the named providers first, so the providers that answered them resume their sessions and the others are handed what they missed. More realistic, but costs usage and varies.
  • "Copy turns from a chat" turns a real conversation into a scenario's setup, such as one where a handoff went wrong.
  • The run view shows exactly what the provider was handed, so a failure can be traced to the handoff or to the model.
  • New checks: only_files_changed, no_question_asked.

Open questions

  • Run cells one at a time (as now), or one per provider in parallel? Parallel is faster, but uses several subscriptions at once.
  • Should the judge's provider be chosen per grader, or always "a different provider from the one being graded"?
