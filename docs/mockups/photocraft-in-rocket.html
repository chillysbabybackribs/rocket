PhotoCraft inside Rocket

PhotoCraft becomes a section of Rocket, like the Browser and the Library. Any provider in the chat can run every PhotoCraft command, bring in images from the web or from Codex's image generator, and save or export the result. You can click into the same canvas at any time.

Where PhotoCraft runs

PhotoCraft's own web build (apps/photocraft-web: egui in the browser, WebGPU with a WebGL2 fallback) runs in a Rocket view beside the chat, the same way a browser tab does. It looks and works like the desktop app.
  • Today the web build has no control channel; only the desktop app has --control. Our fork adds one to the web build that calls the same command registry.
  • The web build can't read the disk, so Rocket hands it files and saves what it exports.
  • Not yet checked: WebGPU in Rocket's Electron on this Linux machine.

What the models can do

Every PhotoCraft command, through tools that copy the names of PhotoCraft's own MCP bridge: command_run, command_batch, command_list, doc_new / open / save / export / inspect, ui_screenshot, ui_pointer, ui_menu_invoke, ui_set, plus place for putting an image in as a layer.
  • Rocket serves them from its one MCP server, so Claude, Codex, Cursor and Antigravity all get them.
  • Ahead of each message the model is told the open document, its size and its layer tree.

Getting images in

  • Web: the existing web_search, web_read and browser_download tools.
  • Codex: a new image_generate tool runs Codex's built-in generator (gpt-image-2), so Claude or Cursor can ask for an image too. A Codex turn uses it directly. Image turns use Codex usage 3–5× faster than text, so the Codex meter is shown.
  • Every image lands in the Library and in this tray; this depends on the Codex image fix now under way in another chat.

You and the model share it

  • You can click into the canvas at any time. Take over pauses the model's PhotoCraft tools until you hand it back. Search and image generation keep working.
  • A model's steps are marked in PhotoCraft's History, and Undo Claude's reply steps back to where the reply began.
  • A cursor labelled with the model's name shows where it is pointing and drawing.

In Rocket's app map

Place photocraft {doc?}. Actions photocraft.open {path}, photocraft.export {format, path}, photocraft.takeOver, photocraft.handBack, photocraft.stop. Its state lives in store.ts, so the toolbar buttons and the models go through the same dispatcher.

No chat inside PhotoCraft

Rocket's chat is the chat. The PhotoCraft panel needs no chat panel of its own, and its toolbar keeps only what belongs to the document: document tabs, Open, Export, Take over and Undo.
